# Financial context JSON export
Objective: generate local, interpretable financial context in full-data or active-filter mode. Initial delivery is committed on main; the compact-format and download follow-up is verified, reviewed and authorized for delivery to origin/main.
Delivery: direct to main at the user's request; keep the feature, tests and user documentation together, with registry metadata in a separate commit. Route: inline implementation, delegated long checks and independent privacy/scope verification. Tests: tsx node tests, Vitest, TypeScript, oxlint, focused browser tests.

## Specs
- S1 — Original request: “Me gustaría añadir una opción para generar un texto json con toda la información de la aplicación utilizando los filtros activos. De esta forma, podré sacar todo el contexto de mis finanzas utilizando esta funcionalidad para poder dar contexto a otros chats de IA.” Export financial summaries and supporting matching movements, not an application restore backup; record date, scope, filters, units and limitations.
- S2 — Scope clarification: “Entiendo que sólo tiene sentido no utilizar los filtros, utilizando todos los datos; o utilizar los datos filtrados. ¿Tu qué opinas, sabiendo que el objetivo es dar contexto a otra IA?” Offer explicit all-data and active-filter modes, defaulting to active filters. Do not change the application's filters. Filtered mode excludes out-of-filter historical movements and historical account balance fields; unsupported analyses are unavailable, not zero. Full mode includes all normalized active financial data and account balances.
- S3 — Approval: “Puedes implementar”. Implement local JSON generation, readable preview and copy action; explain sensitive data and manual sharing. Respect vault locking and current filters; no automatic external transmission or persistence of plaintext exports. Preserve existing navigation and compact toolbar.
- S4 — Quality: verify filtered/full scope, no mutation of data/filters, meaningful metadata, empty results, clipboard failure, mode changes and vault locking using synthetic fixtures. Reuse existing domain calculators. No dependencies, deployment, or unrelated implementation changes. Delivery authorization is defined separately in S5.
- S5 — Delivery: “Incluye todos los cambios pendientes. Haz commit y push a main”. Include the pre-existing registry metadata changes; use Conventional Commits without AI attribution and push main without force.
- S6 — Size audit: “El JSON generado creo que es muy grande. Revisa a fondo el JSON resultante y busca la forma de optimizarlo al máximo para obtener toda la información posible en el menor tamaño posible, siendo lo más comprensible posible para una IA.” Measure existing output locally, distinguish lossless reductions from semantic tradeoffs, and recommend a comprehensible format; the audit itself was read-only; S8 separately authorizes implementation.
- S7 — Resume and download: “La conversación se ha interrumpido. Continua con la tarea y añade también la tarea de añadir un botón de descarga del json. Al ser el archivo tan grande, la función de copiar funciona muy lenta.” Add an explicit local download of the generated JSON without using the clipboard, changing filters or regenerating data. Preserve snapshot invalidation and explain that downloaded files are unencrypted and survive vault locking.

- S8 — Compact format approval: “Si” in response to “¿Implemento el formato compacto propuesto, conservando toda la información del JSON actual?” Implement self-contained versioned compact JSON with descriptive transaction columns, shared value dictionaries/identifiers and constant defaults. Preserve every current JSON value, scope, units and analysis; prove exact reconstruction, meaningful size reduction and unchanged copy/download invalidation.
