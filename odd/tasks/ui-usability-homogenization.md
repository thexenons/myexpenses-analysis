# Financial UI usability and consistency

## Outcome and authority
Improve readability, accessibility, task focus, and visual consistency across the common UI layer and all nine primary routes. Keep the existing brand, financial meanings, and working interaction patterns; reuse components only when their semantics agree. The user authorized a research-led audit and subsequent justified local implementation, with eventual clean-worktree integration and push to `main`. This document plans the UI work; it does not authorize production access, deployment, new dependencies, or private-data inspection.

The feature is distinct from [conventional combined filter facets](combined-filter-facets.md): its T2 owns the filter drawer, chips and counts, and its T3 owns precise Patterns payee/method drilldowns. This feature may improve their surrounding presentation and accessibility, but must not duplicate those tasks or change the accepted filtering semantics.

## Problem and evidence
The source and a rendered Chromium 153 audit covered all 134 page-local production files (52 financial, 82 exploration), shared components, and nine primary routes. Synthetic anonymous data were used at 1280, 390, and 320 CSS px. No document-level horizontal overflow occurred. The audit screenshots are ephemeral local evidence under `/tmp/myexpenses-ui-audit-20260928/screenshots/`, not deliverables. No private vault or outbound request was used.

## Design and evidence rules

- Start from existing shared components. Candidate consolidations: disclosure/detail list; Overview/Cash Flow financial fact list; a named/focusable shared table scroller; numeric type scale; shared category-row styling on the existing `AccordionTree`; and ranked-breakdown slots only if payee and method anatomy genuinely matches. Do not merge `ChartDataTable` and `DataTable` merely because both contain rows, or create a boolean-heavy universal component.
- Prefer aligned position and length for comparisons where the task benefits; retain charts that communicate better with their paired data table. Give charts meaningful statistical descriptions, not geometry alone. Reuse native disclosure and restore focus when controls unmount.
- Meet WCAG 2.2 AA checks for reflow, 200% resize text, text contrast (4.5:1 normal, 3:1 large), non-text contrast (3:1), label in name, focus not obscured, status messages, and 24 × 24 CSS px target size subject to documented exceptions. Prefer comfortable 44 px targets where layout permits; do not claim that as the AA minimum. Verify keyboard and focus flows, not only axe.
- Keep UI copy in neutral professional Spanish; code, tests and documentation in English. Do not invent financial partitions, relabel categories, weaken exception visibility, or turn summary-to-contribution navigation into a new automatic filter semantics. It is an optional opportunity requiring its own product decision.
