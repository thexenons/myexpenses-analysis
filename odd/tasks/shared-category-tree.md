# Reusable accordion category trees

## Outcome and authorized scope

Show every category depth represented by the filtered data in `/comparativa`, and use a shared accordion presentation for hierarchical categories in `/categorías`, `/presupuestos`, and `/comparativa`. Only `/categorías` exposes a category-selection action that changes filters. Expansion/collapse must never filter on its own. Preserve financial calculations, filter semantics, category averages, budget amounts, existing perspective controls, and unrelated views. No dependencies, private data, deployment, or remote delivery changes are authorized by this request.

## Verified starting point

- Base: `main` at `4cdea655bccac8eea88aa53bd7013b1fd939ef3f`; clean before work. Feature branch: `feat/shared-category-tree`.
- `/comparativa` currently has aggregate income/expense/transfer/net values, but no category rows. Its category breakdown is new functionality, not an existing root-category limit to remove.
- `/categorías` recursively renders `CategoryBreakdownNode` with separate disclosure and selection buttons; summaries roll up descendants, while direct summaries describe exact paths.
- `/presupuestos` flattens `BudgetAllocationNode` into an indented table. Its category identity and budget metrics differ from category analytics; the shared presentation must not couple either domain model to the other.
- No other hierarchical category display was found. Category filter controls and flat labels/rankings are not tree renderers and are outside this refactor.

## Design constraints

- Share hierarchy structure, indentation, disclosure styling, accessible names/relationships, and expansion behavior. Keep consumer-specific metrics and category selection separate through a small composable API, not many behavior booleans or a new domain abstraction.
- Native disclosure buttons with `aria-expanded`, unique `aria-controls`, visible focus, and keyboard support. Leaf nodes have no inactive disclosure control. Do not nest selection buttons inside disclosure buttons. Preserve existing initial expansion and selected-category visibility behavior on `/categorías`.
- Comparison keeps its existing full-period overview. Add a category tree with three perspective columns and a metric selector for net (default), income, expense, and transfers, matching the existing signed analytics fields without a twelve-column table. All nested categories represented by the filtered postings must be reachable, including categories unique to one scope and direct postings on parents. Missing scope values are zero; rollups must not double-count children. No root-only depth/series cap or percentages.
- Build category breakdowns independently from the same effective filters for each scope. Preserve account intersection, deferred search, operation/value dates, category matching, statuses, tags, and link filters. Disclosure and metric choice do not mutate global category filters. `Yo` remains `all`; debt movement is not attributed spending or balance.
- Budget accordions retain assigned, rollover, consumed, available, utilization, status, currency/fraction digits, and filtered-comparison labels. Category names must not offer filtering there. Keep any existing empty-state and accessibility behavior.
- Technical artifacts use English; existing UI uses neutral Spanish. Do not rename the all-time period option `Todo`.
